# AGENTS.md — обязательные правила разработки uUnityBridge

> Распространяется на разработчиков, AI-кодинг-агентов и последующие чаты.
> **Не является** автоматически исполняемым набором инструкций уже установленного
> `uUnityBridge.Agent.exe 0.2.1`. Правила локального приложения — в `agent/GOAL_REPORTING.md`.

## Главная цель (не подменять обновлятором)

Через обычный ChatGPT дать пользователю возможность **без терминала на каждом шаге**:
1. создавать/изменять сцену в настоящем проекте Unity через **контролируемый Unity Editor C# API**;
2. получать задания через разрешённый локальный API/ограниченный GitHub relay;
3. запускать разрешённые проверки, видеть результат в Unity;
4. получать **снимок только явно разрешённого окна** с подтверждённой приватной доставкой;
5. повторять цикл ChatGPT → код/PR/CI → безопасная доставка → Unity → отчёт/скриншот → ChatGPT.

Нельзя подменять Unity Editor интеграцию просто зелёными CI или очередным обновлятором.
Не реализовывать произвольную инъекцию исполняемого кода, удалённый shell или админ-API.

## Источники правды и история версий

- `CONTINUE_HERE.md` — текущая контрольная точка для продолжения другого чата.
- `version.json` — структурированный **документальный снимок** версий, целей и доказательств.
- `version.md` — человеческая хронология принятия решений и результатов.
- `version.html` — доступная статическая визуальная история (не доказательство выполнения).
- `docs/GOALS_AND_ACCEPTANCE.md` — план, критерии и порядок достижения.
- `agent/GOAL_REPORTING.md` — правила безопасной отчётности локального агента.
- GitHub PR, Issue, CI, Release и локальная приёмка пользователя — первичные источники фактов.

При изменении статуса этапа сверять первичные источники, обновлять **все** четыре
документа (`CONTINUE_HERE.md`, `version.md`, `version.json`, `version.html`)
и критерии приёмки. Файлы не обновляются автоматически существующим
Agent 0.2.1 — синхронизацию ПК отдельно подтверждать.

## Запрет ложного «готово»

Статусы различаются:
- `planned`: только замысел;
- `in_development`: код создаётся;
- `ci_pass_qa_pending`: CI PASS, нет реальной пользовательской/VM приёмки;
- `qa_pass_release_pending`: E2E в изоляции подтверждён, релиз не выпущен;
- `released_install_pending`: релиз есть, установка и реальная проверка нет;
- `done`: все проверки этапа завершены, ссылки на доказательства сохранены.

`DONE` разрешён **только**, если есть: код/PR, требуемые Windows CI,
реальный сценарий исполнения, опубликованный релиз (когда нужен),
локальная приёмка (когда нужна), подтверждение видимого результата в Unity
(для Unity-целей) и обновлённые документы. Только локальные тесты в GitHub
Actions или статусы `status PASS` **не** доказывают установку/Unity.

## Обязательное завершение каждой задачи/патча

1. Проверить актуальные PR, Issue, Release, CI и подтверждения пользователя.
2. Перечислить: что работает; что только в PR; что НЕ работает; что на ПК не менялось.
3. Для каждой цели указать результат, доказательство, статус и следующий шаг.
4. Если **все** согласованные цели/долги/патчи завершены по критериям:
   вывести чёткое сообщение **«ТЕКУЩИЙ НАБОР ЦЕЛЕЙ ЗАВЕРШЁН. НУЖНЫ НОВЫЕ ЦЕЛИ»**;
   привести ссылки на проверки и попросить пользователя сформулировать новые.
5. Если хоть одна цель не закрыта — не заявлять полного завершения, а назвать
   конкретный блокер и ближайший наблюдаемый результат.
6. ChatGPT не наблюдает GitHub непрерывно сам по себе. Проактивное уведомление
   возможно только через отдельно включённую автоматизацию/мониторинг.
   Не утверждать, что уведомление настроено, пока оно не создано.
7. При правках в PR #25 не устанавливать EXE, не менять рабочие файлы ПК и
   не публиковать стабильный Release до безопасных gate-проверок.

## Действия пользователя: максимум ясности

Каждая инструкция пользователю должна содержать 1–3 конкретных действия
и ожидаемый видимый результат. Не заставлять пользователя вручную
переносить EXE/вести консоль, если возможно сделать через GUI.
Если не подтверждено, что Unity Hub, Editor и тестовый проект установлены,
не объявлять интеграцию готовой. Не запрашивать приватные данные и скриншоты
полного рабочего стола.

## Перед началом новой сессии

Прочитать `CONTINUE_HERE.md`, `version.json`, `version.md`,
`docs/GOALS_AND_ACCEPTANCE.md` и `agent/GOAL_REPORTING.md`;
проверить GitHub заново. Не считать описания реализации подтверждением
фактической установки на Windows.
