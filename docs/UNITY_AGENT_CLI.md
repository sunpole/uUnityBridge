# Unity через uUnityBridge: локальный API, статус и создание проекта

**Контрольная точка:** 2 ноября 2026. **Реализация — только Draft PR #30; не установлена на рабочем ПК.**
**Unity Editor пользователя:** Unity 6.6 `6000.6.7f1` установлен по скриншоту Hub;
наличие и открытие `uUnityDemo` не подтверждены.

## Действия в будущей версии uUnityBridge Desktop / Agent

Новый интерфейс Desktop:
- **UNITY · ПАПКА** — выбрать существующий родительский каталог
  (например `C:\!CODE_CLUB\new 2026\017_uunity`),
  подтвердить локально разрешение только на `uUnityDemo`. Файл
  `%LOCALAPPDATA%\uUnityBridge\unity-approval.json` хранит путь
  и `enabled`. Никакое GitHub Issue не меняет разрешение.
- **UNITY · СТАТУС** — выполнить `unity_status` через
  Windows Named Pipe текущего пользователя; CLI проверяет связь
  с работающим Unity Editor, при отсутствии готовности ответ `BLOCKED`.
- **UNITY · СОЗДАТЬ** — выполнить `unity_project_create` через Named Pipe:
  фиксированный проект `uUnityDemo`, Unity `6000.6.7f1`, 2D,
  `--no-cloud`, `--with-pipeline`. Только если каталог проекта
  **ещё не существует**; не перезаписывать данные.
- **UNITY · ОТКРЫТЬ** — выполнить `unity_project_open`, только если
  проект содержит `Assets` и `ProjectSettings/ProjectVersion.txt`.

Локальная передача: Desktop → `uUnityBridge.Agent` → **Unity CLI**
→ Unity Editor (через Unity Pipeline). Вызывается **только** процесс `unity`
с заранее заданными аргументами из кода; `cmd.exe` и
`powershell.exe` не применяются. Входное JSON в локальном IPC
содержит только одно поле `action`:
```json
{"action":"unity_status"}
```
```json
{"action":"unity_project_create"}
```
```json
{"action":"unity_project_open"}
```

Отчёт на создание/открытие сначала `ACCEPTED` — операция
запущена, **не** означает, что закончилась. Через последующий
`unity_status` проверяется готовность. Нет автоматической отправки
путей, CLI stdout/stderr, авторизационных ссылок и скриншотов в GitHub.

## Ограничения и безопасность

- Разрешение назначает только локальный пользователь в Desktop GUI.
- API не принимает внешний путь, имя проекта, URL, флаги CLI, shell,
  произвольный C# код или исполняемые файлы.
- `UNITY_NO_CLOUD=1`; Editor выбирается по фиксированной версии,
  установленной у пользователя.
- Проект `uUnityDemo` является отдельным тестовым, старые каталоги
  и `uUnityBridge_App` не перезаписываются.
- Одновременно выполняется одна операция create/open. Отдельно ограничен
  срок ожидания CLI; `unity_status` не передаёт сырой лог наружу.
- В текущем GitHub relay **только** действие `status`:
  `unity_project_create` и `unity_project_open` пока не принимаются
  из GitHub Issues. Это отдельный будущий этап с журналом заданий,
  идемпотентностью и подтверждением выполнения (не просто `ACCEPTED`).
- `Agent 0.2.1` и Desktop `0.4.2`, установленные на ПК, новые
  кнопки/действия **не содержат**. Потребуются безопасная приёмка,
  выпуск и обновление; PR #25 отвечает за доставку и откат.
- Связь с настоящим Unity Editor **НЕ подтверждена**: Unity CLI
  пока не запускался через новый Agent на пользовательском ПК.
- Этот механизм ещё не устанавливает пакет из PR #30 и не создаёт
  3 платформы автоматически; для этого нужен отдельный безопасный
  Editor command adapter после проверки Unity Pipeline.

## Проверки

- `tests/uUnityBridge.UnityBridgeTests` — на изолированном Windows CI
  проверяет фиксированные аргументы, единственный `uUnityDemo`,
  отказ при существующей папке, неверной структуре проекта и
  попытке передать произвольное действие/путь.
- `agent --self-test` — мок-тест трёх типизированных IPC действий
  и блокировки дополнительных JSON-полей.
- `.github/workflows/agent-windows.yml` — запуск обоих тестовых наборов
  в CI + сборка standalone Agent.
- `.github/workflows/windows-build.yml` — сборка Desktop с новыми кнопками.
- **До реального Unity E2E ни одна цель не получает статус DONE.**

## Первичная приёмка после безопасного обновления

1. Пользователь открывает **новый** Desktop и в `UNITY · ПАПКА`
   выбирает родительский каталог и подтверждает разрешение.
2. Нажимает `UNITY · СОЗДАТЬ`, затем `UNITY · ОТКРЫТЬ` после завершения.
3. После запуска Unity Editor получает `UNITY · СТАТУС` и подтверждает
   наличие настоящего проекта `uUnityDemo`.
4. Проверяется установленный Unity Pipeline. Только затем безопасно
   испытывается создание/сохранение сцены через Editor package PR #30.
5. Запрашиваются отдельные доказательства скриншота одного окна и полного
   ChatGPT→GitHub→Windows→Unity цикла. Не заявлять, что они уже работают.
