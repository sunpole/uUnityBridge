GitHub Actions после объединения изменений в main только **собирает
ретроспективные ZIP в артефакт CI**, используя указанные исходные коммиты.
GitHub не выдаёт встроенному токену разрешения создавать теги на старых
коммитах, содержащих изменённые workflows. Поэтому публикация выполняется
однократно от имени владельца через уже подключённый gh CLI.

Скрипт scripts/Publish-History-And-Clean.ps1 проверяет пользователя
sunpole, успешную сборку на точном SHA актуальной main, SHA256 каждого EXE,
версию и исторический Git-коммит. Только после этого он создаёт Releases
для v0.1.0–v0.4.0 и не изменяет v0.4.1/v0.4.2. С флагом -Clean он также
запускает отдельную проверяемую очистку старых QA-папок.

**Предупреждение:** ретроспективные EXE не обязательно идентичны
оригинальным файлам на пользовательском ПК. Их имена содержат
HISTORICAL-REBUILD, а release notes явно объясняют происхождение.
Исходники доступны через GitHub Source code archives. При повторном
запуске существующие Releases не перезаписываются.

## Постоянная установка

Папка, которую защищаем от очистки:
C:\!CODE_CLUB\new 2026\017_uunity\uUnityBridge_App

Папка исходников Git, которую также защищаем:
C:\!CODE_CLUB\new 2026\017_uunity\uUnityBridge

Не трогаем пользовательский Unity_ReadOnly_Diagnostics.ps1,
корзину других программ, настройки и ответы в %LOCALAPPDATA%\uUnityBridge,
ярлыки рабочего стола и пользовательские документы.

## Что может быть очищено

Только три явно разрешённых тестовых каталога:
- QA-0.2.1
- QA-0.3.0
- QA-0.4.0 (даже если его EXE уже обновлялся до 0.4.2)

Локальный скрипт scripts/Clean-Local-QA.ps1 сначала проверяет:
1. Живую постоянную установку и версию 0.4.2.
2. Наличие архивов семи указанных Releases с вложениями.
3. Отсутствие дополнительных подпапок, ссылок, файлов с неизвестными
   именами или неожиданных версий EXE.
4. Что перед очисткой закрыты все процессы uUnityBridge.

Без флага скрипт только показывает план. С явным флагом -Clean
переносит только прошедшие проверку QA-копии в Корзину Windows,
откуда их можно вернуть. Для полного освобождения места пользователь
должен отдельно очистить Корзину после проверки.

**Скрипт никогда не загружает с пользовательского ПК его личные файлы
на публичный GitHub**. Исторические сборки выполняются исключительно
в GitHub Actions из уже опубликованных исходных коммитов.

## Граница безопасности

Версия 0.4.2 не умеет исполнять произвольные команды из GitHub Issues.
Это не разрешается даже в режиме автоматического обновления.
Поэтому для первого запуска операции локальной очистки требуется
явное действие пользователя; удаление по публичному PATCH запрещено.
