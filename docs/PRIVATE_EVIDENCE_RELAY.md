## Подтверждённая отправная точка

Пользователь управляет домашним ПК через AnyDesk с телефона. Локальный захват
Unity Editor `uUnityDemo` 1936×1056 реальным QA-агентом был подтверждён.
Пользователь не должен вручную переносить изображения в ChatGPT.

Нынешний QA Desktop записывает **два локальных файла** в профиль пользователя:

- `%LOCALAPPDATA%\uUnityBridge-QA\captures\latest-unity-window.png`;
- `%LOCALAPPDATA%\uUnityBridge-QA\captures\latest-unity-evidence.json`.

Манифест содержит `schema`, `project`, `editorVersion`,
`capturedAtUtc`, `width`, `height`, `imageSha256`,
`imageBytes`, `scope=approved_window_only`,
`transport=LOCAL_ONLY`, `uploadPermitted=false`.
**Нет** локального пути, текста окна, ключей или полных журналов.
Запись этого файла не является разрешением на отправку.

## Следующий безопасный этап: приватный доставщик

Пока пользователь не выбрал приватное хранилище и не подтвердил
его доступность ChatGPT, никакие PNG/логи нельзя загружать в сеть.

1. Выбрать отдельный **закрытый** ресурс (не публичный
   `sunpole/uUnityBridge`, не prnt.sc) с правами загрузки только агента
   и чтения только через подключённый коннектор пользователя.
2. В QA GUI запросить явное локальное согласие: точный адрес назначения,
   только `uUnityDemo`, разовая/отзывная отправка, максимальный размер,
   срок хранения, тип результата (один PNG + очищенный отчёт).
3. Запретить произвольные URL и paths из GitHub Issues или ChatGPT.
   Перед загрузкой повторно проверить, что назначение **не публичное**.
   Если приватность проверить нельзя, результат `BLOCKED_STORAGE_PRIVACY`,
   кадр остаётся только на ПК.
4. Сверить SHA-256 сохранённого PNG с манифестом, проверить лимит размера
   и отсутствие лишних файлов/журналов. Передавать только явный разрешённый
   артефакт.
5. После загрузки сохранить машинный результат `upload_status`,
   `evidence_id`, `sha256`, `received_at_utc`; открыть файл
   **реально через коннектор ChatGPT**, а не просто проверить HTTP 200.
6. Предусмотреть удаление по запросу, ограничение повторов,
   отсутствие дублирования, приватность лога, обработку ошибки сети
   без публикации в публичные Issues.
7. В GitHub Issues допускаются только безопасные технические статусы.
   Не загружать бинарники, изображение, stdout/stderr или секреты в открытый
   GitHub без отдельного разрешения.
