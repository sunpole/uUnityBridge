# P0015 — локальный снимок окна Unity и блоки ошибок консоли

**Статус: разработано в Draft PR #30; Windows QA и приватная доставка в ChatGPT НЕ подтверждены.**

## Почему это приоритет

Владелец управляет домашним ПК с телефона через AnyDesk. Перенос изображений в ChatGPT вручную непрактичен. Публичный сервис prnt.sc ненадёжен для автоматической обработки и не подходит для приватного отчёта.

## Что добавлено

### UNITY · ЛОГИ

Desktop по CurrentUserOnly Named Pipe отправляет агенту только `{"action":"unity_diagnostics"}`.
Агент возвращает локальный компактный отчёт с тремя полями статуса и **двумя отдельными блоками**:

1. **КОНСОЛЬ UNITY CLI:** последний завершившийся CLI-запрос, код результата и последние 10 строк ошибок/предупреждений, включая stderr и stdout. CLI логи ограничены при чтении, сохранена только часть последних строк. `ACCEPTED` по-прежнему означает старт, не итог.
2. **КОНСОЛЬ UNITY EDITOR:** до 10 строк с Error/Exception/Failed/Warning из хвоста стандартного `Editor.log`. Читается **только** после локального разрешения проекта и если заголовок журнала подтверждает полный путь согласованного `uUnityDemo`. Если проверить источник не удалось, блок пустой.

При формировании отчёта скрываются токены, URL, email, полные Windows/Linux пути и управляющие символы. Ограничены длина строк и объём отчёта. **Фильтрация — дополнительная защита; никаких автоматических публичных публикаций текстовых логов нет.**

### UNITY · КАДР

В QA Desktop добавлена **явная локальная кнопка** одноразового снимка. Для него нужны:
- `UUB_UNITY_QA=1`, локальное разрешение на тестовый `uUnityDemo`;
- существующий видимый, не свёрнутый процесс Unity Editor `6000.6.7f1`;
- точно сопоставленное имя проекта в заголовке окна и проверенный путь к `Unity.exe`;
- ровно одно подходящее окно.

Применяется Windows `PrintWindow` к одному HWND, **не захват всего экрана**. Снимок сохраняется **только локально**:
`%LOCALAPPDATA%\uUnityBridge-QA\captures\latest-unity-window.png`.
Открывается окно локального просмотра. Публичный GitHub, prnt.sc и ChatGPT изображение не получают. При ошибках — явный `BLOCKED`, а не ложный PASS.

**Возможное ограничение:** аппаратное ускорение Unity может приводить к пустому/чёрному снимку через `PrintWindow`. Требуется проверка на настоящем ПК; не считать это гарантированно работающим скриншотером.

## Граница готовности

| Этап | Что доказывает | Статус |
| --- | --- | --- |
| Windows CI компиляции и фильтрации журналов | Код собирается, тесты проходят | Требуется подтверждение для точного HEAD |
| Локальная кнопка UNITY · ЛОГИ | Агент реально возвращает ошибки установленного Unity | Не проверено на ПК |
| Локальная кнопка UNITY · КАДР | Отображает изображение только разрешённого окна | Не проверено на ПК |
| Приватная автоматическая доставка снимка/лога в ChatGPT | ChatGPT действительно открывает и анализирует изображение без AnyDesk | **НЕ реализовано** |
| Полный удалённый запрос ChatGPT → Unity → результат/снимок | Вся цепочка подтверждена пользователем | **НЕ реализовано** |

## Следующий шаг после CI

1. С помощью `scripts/Stage-Unity-QA.ps1` получить две сборки **из одного точного проверенного HEAD**, не заменяя рабочую установленную версию.
2. Открыть только QA Desktop + QA Agent в отдельном режиме.
3. Нажать `UNITY · ЛОГИ` и `UNITY · КАДР`, сверить с текущим окном Unity.
4. Подключить отдельное **закрытое хранилище** изображений с согласия пользователя и явно проверить доступ из ChatGPT через подключённый коннектор. Не публиковать изображения в открытом GitHub.
5. Затем добавить типизированную команду агента для capture и защищённую доставку с конечным статусом `PASS/BLOCKED`, лимитами размера, сроком хранения и механизмом удаления.
