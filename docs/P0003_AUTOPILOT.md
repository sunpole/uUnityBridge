# uUnityBridge 0.3.0 — локальный агент (прототип P0003)

## Одна кнопка, автоматическая работа

Пока окно запущено, приложение:
1. Сразу при старте опрашивает GitHub (авторизованный `gh` аккаунт `sunpole`).
2. Каждые **60 секунд** ищет до пяти открытых допустимых PATCH от `sunpole`.
3. Без повторного подтверждения применяет **только** `report-only` или Git `sync-main` с проверенным SHA, чистым деревом и checkpoint.
4. После обработки публикует ANS, затем закрывает завершённый Issue.
5. При появлении ранее не скопированных ANS активирует единственную большую кнопку **«ОТЧЁТ · N НОВЫХ»**.
6. Кнопка копирует все новые ANS и ссылки в буфер обмена, затем сохраняет отметки. Повторное нажатие не копирует старые ответы.

Если GitHub недоступен, программа увеличивает интервал до 2, 4, 8, 16 и максимум 30 минут. При ошибках конкретного PATCH — паузы 5 и 15 минут перед второй и третьей попытками; после 3 ошибок задание помечается BLOCKED, публикуется итог и закрывается как not planned.

**Важно:** защита от повторов и автопубликация не равно автообновлению бинарного EXE. `sync-main` обновляет только доверенные исходники. Без нового отдельного проверенного обновлятора EXE не заменяется. Команды PowerShell из GitHub Issues не выполняются.

Одна копия текущего агента запускается одновременно. Функция работает **только пока приложение запущено**: не установлена фоновая служба, автозапуск Windows не включён.

## Локальная история

- `%LOCALAPPDATA%\uUnityBridge\answers.json`: статусы PATCH, ANS и ссылки.
- `%LOCALAPPDATA%\uUnityBridge\report-cursor.json`: идентификаторы уже скопированных результатов.
- Оба файла записываются с резервной копией; секреты не записываются.
- При первом переходе с 0.2.1 старые отправленные ANS считаются уже просмотренными, чтобы не повторять P0001/P0002.
- Если история повреждена, приложение останавливает обработку вместо повторного выполнения.

## Безопасность и нагрузка

Программа использует CLI `gh` и проверяет автора задания, формат, точный SHA, Git remote и текущую ветку. Не выполняет команды из публичного текста Issue.

60-секундный интервал — рекомендованное начальное значение для **локального компьютера без публичного webhook endpoint**. Это не гарантия отсутствия rate limits: GitHub также применяет вторичные лимиты. Если будет нужна высокая масштабируемость, перейти на webhooks и проверку HTTP ETag/If-None-Match.
