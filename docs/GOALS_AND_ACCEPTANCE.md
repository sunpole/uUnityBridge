## Главная цель

ChatGPT получает пользовательскую задачу на русском, меняет разрешённый Unity-проект
через редакторный Unity C# API, сохраняет сцену, возвращает доказательство результата
(версия, лог и, после отдельного согласия, снимок **только выбранного окна**).
В штатном цикле пользователь не переносит EXE и не вводит команды в PowerShell.

## Границы и метод разработки

1. Изменять только разрешённые Unity-проекты и тестовые каталоги.
   Не трогать постоянный `uUnityBridge_App` без отдельного согласия пользователя.
2. **Не использовать произвольную удалённую инъекцию кода.**
   Unity управляется набором фиксированных и проверенных команд через Unity Editor scripting API.
3. Для локальной диагностики достаточно текущего Agent 0.2.1 (`status`);
   он не поддерживает Unity, скриншоты или `install_release`.
4. Тестовые ветки/PR и CI не заменяют проверку установленного ПО.
5. Не отправлять скриншоты в публичный GitHub, не считывать токены и личные файлы.
6. На каждом законченном этапе сообщать «видимый результат / что НЕ готово / что делаем дальше»
   и обновлять `version.json`, `version.md`, `version.html`, `CONTINUE_HERE.md`.

## Что сделать пользователю сейчас

1. Если Unity Hub отсутствует, установить его с официальной страницы [Unity](https://unity.com/download); войти в Unity Hub и установить **Unity 6.3 LTS** через **Installs → Install Editor**. Операции установки выполняет пользователь в Windows, не удалённый агент.
2. Создать или открыть **отдельный пустой тестовый 2D-проект**, например `uUnityDemo`.
   Не использовать рабочий проект и не запускать чужие скрипты.
3. Оставить Unity Editor открытым и сообщить в чат **версию Unity Editor** и
   **название тестового проекта** (путь к личным файлам присылать не нужно).

Для разработки на GitHub основной `uUnityBridge.exe` и PowerShell открывать не нужно.
Установленный фоновый Agent может работать в обычной Windows-сессии самостоятельно.

## Как завершать каждую цель

Перед выставлением `done` проверить:
- фактические исходники, PR/commit и тесты;
- релиз и SHA256 при доставке бинарника, подпись/аттестацию где требуется;
- пользовательскую/VM приёмку целевой операции;
- снимок/лог **именно Unity**, если критерий связан с Unity;
- безопасность, откат, повтор и отсутствие записи вне разрешённых путей;
- обновлённые документы и явный вывод пользователю.

При любых отсутствующих проверках оставить `planned`, `in_development`,
`ci_pass_qa_pending` и указать, чего именно не хватает.

Если **все согласованные blocking goals** из `version.json` подтверждены как
`done` с первичными доказательствами, сообщить пользователю:
**«ТЕКУЩИЙ НАБОР ЦЕЛЕЙ ЗАВЕРШЁН. НУЖНЫ НОВЫЕ ЦЕЛИ»**
и попросить определить следующую задачу. До этого момента закрывать проект нельзя.

## Что означает «уведомить потом»

Текущий Agent 0.2.1 **не следит** за `version.json` и не может сам
отправить уведомление ChatGPT о завершении разработок.
Текст правил не создаёт планировщик. Для проактивного сообщения
должна существовать отдельная включённая условная автоматизация.
На 1 ноября 2026 такая **ежедневная условная автоматизация ChatGPT
настроена**. Она не является частью Agent 0.2.1 и не влияет на локальные
файлы, Release или статус целей без независимого подтверждения.
Автоматизация может лишь **проверять доказательства и уведомлять**;
она не заменяет написание кода, CI или приёмку пользователем.
