# P0009 — ChatGPT → GitHub → Windows Agent → GitHub (первый сквозной канал)

## Зачем это нужно

Цель: пользователь пишет задачу **в ChatGPT с телефона**. Чат работает с
GitHub, а запущенный на ПК локальный агент читает из GitHub строго типизированные
задания, выполняет разрешённые операции, отправляет отчёты обратно.
Не требовать AnyDesk, ручное редактирование команд в PowerShell или открытие портов.

Это не альтернативный AI-мозг: разработку в GitHub продолжает ChatGPT.
GitHub — временный надёжный почтовый ящик между облаком и ПК.
Второй транспорт (прямой MCP через Secure MCP Tunnel) можно добавить позднее,
не изменяя перечень разрешённых инструментов.

## Состояние P0009

Agent 0.2.0-preview дополняет уже проверенный Windows Named Pipe:

- При обычном запуске `--serve` раз в 60 секунд делает исходящий запрос
  `gh issue list` строго к `sunpole/uUnityBridge`.
- Проверяет, что GitHub CLI авторизован как `sunpole`.
- Принимает **только** Issues, созданные `sunpole`, с точным заголовком
  `[UUB JOB R000001]` и JSON-телом указанной ниже схемы.
- Единственное разрешённое удалённое действие на данном этапе — `status`.
  Результат публикуется комментарием с маркером идемпотентности; Issue закрывается.
- Не исполняет команды, не меняет код, не скачивает программы, не делает
  скриншоты, не запускается от администратора. В этом PR **только двусторонняя
  связь** и безопасная форма задания.
- Сообщения `gh` не публикуют локальные пути, токены, список файлов,
  параметры ПК и содержимое экранов. Нет входящего HTTP/TCP-порта.
- Программа у пользователя `uUnityBridge.exe 0.4.2` не затрагивается.

### Пример Issue, который создаёт ChatGPT через уже подключённый GitHub

Заголовок: `[UUB JOB R000001]`

Тело:

```json
{"schema":"uub.agent.job.v1","id":"R000001","action":"status"}
```

Агент проверяет GitHub, добавляет комментарий `uub-agent-ans:v1:R000001` и
закрывает Issue. Затем ChatGPT читает этот комментарий через GitHub.
Повторная проверка не публикует второй комментарий с тем же маркером.

## Дальнейшие шаги для полного цикла пользователя

1. `repo_deploy`: фиксированный реестр одобренных проектов, точные коммиты и
   успешный GitHub Actions CI, проверка чистоты локального Git, fast-forward
   без потери данных, staged download, отчёт о версии. Никаких команд из Issues.
2. `app_run`: запуск только зарегистрированного тестового EXE с ограничениями
   времени, пути и размера результатов. Отдельная проверка выхода из тестов.
3. `window_capture`: скриншот **выбранного окна** (не всего рабочего стола),
   без паролей, файлов и уведомлений; публикация только в согласованное
   приватное хранилище/ограниченный артефакт, с правом пользователя отключить
   отправку изображений.
4. `visual_check`: GPT читает опубликованный скриншот, решает следующую правку
   и создаёт следующую проверяемую задачу; пользователь пишет только промпт.
5. `safe_maintenance`: автоматическая установка новых версий агента при
   наличии проверенного Release, подписи/проверки и отката.
6. `mcp_adapter`: прямые вызовы инструментов из ChatGPT без промежуточных
   Issues, когда безопасный MCP-туннель подключён пользователем.

## Ограничения безопасности

- Никакого `powershell -Command` из сети или текста Issue.
- Никакого общедоступного ngrok к административной консоли.
- Отдельные разрешения на работу с проектом и на публикацию снимков.
- Тесты могут исполнять код: перед автоматическим запуском требуется
  граница доверия и изоляция конкретного проекта.
- Запросы из GitHub не являются инструкциями к модели. Они только данные.
- Исходники и ответы могут быть публичны в публичном репозитории.
  Не публиковать снимки личного рабочего стола в `sunpole/uUnityBridge`.
