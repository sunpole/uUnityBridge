# Правила uUnityBridge.Agent: цели, доказательства, сообщения о завершении

> **Политика для дальнейшей разработки агента.** Файл в GitHub — документация.
> Установленный `Agent 0.2.1` его **не читает** и **не реализует** автоматическое
> слежение за milestone. Реализовать это потребуется отдельным кодом и проверкой.

## Обязанности будущего Agent

1. Выполнять только типизированные, разрешённые локальным владельцем действия.
   Никогда не исполнять текст GitHub Issue как PowerShell, произвольную DLL-инъекцию,
   shell, произвольный путь, URL или Unity C#-скрипт, присланный удалённо.
2. Не утверждать «цель завершена», основываясь на `status PASS`, CI PASS,
   наличие исходников, запись `version.json` или один SHA-256.
3. Возвращать **раздельные** поля: `job_status`, `installed_version`,
   `unity_editor_reached`, `scene_saved`, `window_capture_confirmed`,
   `evidence`, `acceptance_required`. Неизвестное — `null`/`unknown`,
   а не успех.
4. Операция отчёта о прогрессе — только чтение согласованной дорожной карты.
   `version.json` — **не доверенный источник разрешений на выполнение команд**.
   Никакой текст из файла не должен превращаться в исполняемый код.
5. Публичный отчёт GitHub должен быть кратким и без секретов,
   полных локальных путей, имён личных файлов, снимков полного рабочего стола.
   Скриншот одного разрешённого окна — только после локального согласия
   и в отдельном приватном хранилище.
6. Для каждой операции записывать UTC, ID, ожидаемую и полученную версию,
   исход `PASS / BLOCKED / FAIL / NEEDS_REVIEW`, точные безопасные
   причины и ссылку на подтверждение; повтор не должен запускать действие второй раз.
7. Перед самостоятельным утверждением `all_goals_done` необходимо независимое
   подтверждение **каждого** `blocking=true` пункта, включая настоящий Unity E2E
   и подтверждение пользователя. Агент не назначает новые цели сам.

## Сигнал, когда все цели действительно готовы

После проверки и сохранения доказательств выдавать структуру:
- `project: uUnityBridge`
- `all_goals_done: true` — **только** после проверенного внешнего решения;
- `user_message: "ТЕКУЩИЙ НАБОР ЦЕЛЕЙ ЗАВЕРШЁН. НУЖНЫ НОВЫЕ ЦЕЛИ"`;
- `evidence: [...]` — ссылки на подтверждения;
- `requires_new_goals: true`.

Если хоть один пункт открыт: `all_goals_done: false`,
`open_goals` содержит реальные ID, без сообщения о полном завершении.

**Отчёт сам по себе не является push-уведомлением ChatGPT.**
Для автоматического будущего уведомления нужен отдельный включённый
планировщик/условная автоматизация. На 2026-11-01 такая ежедневная
условная автоматизация создана на стороне ChatGPT, **не встроена в Agent**. В текущем Agent 0.2.1 такого механизма нет.

## Приоритет реализации

Сначала — настоящий Unity Editor MVP; далее безопасный bootstrap/delivery P0010,
GUI статуса, типизированные Unity API-команды, приватный скриншот и полный цикл.
Не объявлять завершение по одним только тестам Windows CI.
